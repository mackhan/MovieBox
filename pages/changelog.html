v0.1.68 · 2026-10-20

扫描

  • 快速扫描命中缓存时校验文件是否仍存在（废纸篓恢复、外部新增的文件终于能被发现）
  • 修复缓存命中分支的 O(D×(F+K)) 线性扫描，改为一次性建索引 —— 300 目录 / 6 万条记录下从 1896ms 降到 60ms
  • 目录不可访问（移动硬盘拔出、网盘断连）时保留数据库记录，不再整棵子树删库
  • 读取失败的目录，其下记录不参与「已删除」判定
  • 修复全量扫描会清零播放次数

查重

  • 查重前重新扫描一次（不再只依赖已有列表）
  • 修复 1MB~1MB+64KB 区间加密视频的哈希读到密文、导致漏判
  • 哈希不可信的文件不再参与判重，避免误删
  • 分桶阶段不再白读每个文件 128KB；主线程不再被同步 I/O 卡住

归类

  • 目录内视频全部无名字时，改用目录名作为分组信号（lucynana/hash1.mp4… 这类场景现在能归出来）
  • 「移出组」的人工排除真正生效，重新归类不会再被自动命名覆盖
  • 人脸负缓存增加最少帧数护栏，避免一两次抓帧失败就被永久判为无脸
  • 归类改为批量调用 Python（import 开销从 O(N) 降到 O(1)），显著提速

收藏

  • 修复同名视频串号：收藏 A，同名的 B 也跟着亮 / 取消一个另一个也掉
  • 根因是收藏读取一直走文件名模糊匹配，精确路径匹配从未生效

保险箱

  • 修复「解密后移动到网络盘」必然失败（且文件其实已解密、界面却报错）
  • 加解密按文件串行化，杜绝并发写坏文件头
  • 解密可重入 + meta 先备份后删除，中途崩溃不再留下无法恢复的中间态
  • 加解密 I/O 异步化，批量操作不再卡住界面
  • 文件级并发锁下沉到服务层，文件夹批量加解密不再绕过保护
  • 解密改为「先改名后删 meta」，目标重名自动 _(N)，不再静默覆盖同名视频
  • 加密改名失败会回滚文件头，避免二次加密导致永久损坏

其他

  • 网络盘自动重连改为指数退避并设上限，轮询加并发保护
  • 修复 /Volumes/NAS 不可用时误伤 /Volumes/NAS2；重新挂载会更新凭据
  • 接入自动更新（GitHub Releases），支持 Apple Silicon 与 Intel Mac
  • 新增导出/导入配置（导出自动剔除 API Key 等敏感项，导入做类型校验）
  • 新增「关于」页的隐私政策 / 安全说明 / 更新日志入口
  • 删除视频同步清理收藏，不再留下空名收藏行
  • 补齐日文缺失文案
  • 清理 13 条锁定旧错误行为的守卫测试，改为行为断言

v0.1.67 · 归类落单治理

  • 未归类项由路径数组升级为结构化对象（缩略图 + 建议演员名 + 原因），不再静默丢弃 —— 此前约 68% 视频因此「消失」
  • 新增目录名作为一级分组信号（实测 34/56 视频所在目录名即演员名）
  • 名字组归一化合并，解决「南音」与「南音·alleys」被拆成两组
  • 人脸聚类：同视频多帧只保留主簇、距离改中位数、增加组内一致性校验防链式误并
  • 0 脸时扩大采样区间重试，仍 0 脸且深度模式才用 CNN 兜底

v0.1.66 · 兼容性与提示

  • 文件夹名清洗：非法字符、Windows 保留设备名（CON/PRN/AUX/NUL/COM1-9/LPT1-9）、长度上限
  • 批量移动部分失败时明确提示完成数，不再静默
  • 数据库人名清洗改为保守策略，避免把「Yui Hatano」降维成「hatano」导致同姓不同人被并组
  • 中文/日文人名的长度上限统一为 10

v0.1.65 · 性能

  • 归类组装阶段由 O(n²) 降到 O(1)：一次性建索引，替换 4 处循环内线性查找
  • 上千视频时可省下十万到百万次字符串比较

v0.1.64 · 人名识别

  • 抽出独立的人名识别模块：剥离域名括号、支持多名字组合、拒绝番号厂商前缀与站名句柄
  • 文件名人名提升为一等路径，有名字的视频在人脸聚类前就成组
  • 同目录唯一演员继承；支持整组移入「演员名」子目录
